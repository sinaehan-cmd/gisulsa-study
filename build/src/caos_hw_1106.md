# PART 1. 안 죽는 시스템

## 1-4. Five Nines ☆ (140회)

- 99.999% = **연간 다운타임 약 5분 15초**
- 계산: 가용성 = **MTBF / (MTBF + MTTR)**
  - MTBF = 평균 고장 간격 (길수록 좋음) / MTTR = 평균 복구 시간 (짧을수록 좋음)

| 9의 개수 | 연간 다운타임 |
|---|---|
| 99.9% | 약 8.8시간 |
| 99.99% | 약 53분 |
| 99.999% | 약 5분 |

**140회 구조**
- 이중화 아키텍처: 서버(Active-Active) · 네트워크(이중 스위치·회선) · 스토리지(RAID·복제) · 전원(UPS·이중 전원) · 사이트(DR센터)
- 위협 요소: SPOF · Split Brain · 연쇄 장애 · 인적 실수 · 사이버 공격 · 재해
- 성능 평가: MTBF · MTTR · RTO(복구 목표 시간) · RPO(복구 목표 시점) · 장애 주입 테스트(카오스 엔지니어링)

# PART 3. 가속 HW

## 3-2. CPU vs GPU vs TPU vs NPU ★ (138 정관)

**GPU 정의:** 수천 개 코어로 대량 데이터를 동시 처리하는 병렬 연산 프로세서
**TPU 정의:** 텐서 연산에 특화된 시스톨릭 어레이 기반 구글의 AI 전용 프로세서
**NPU 정의:** 신경망 연산을 저전력으로 가속하는 AI 추론 전용 프로세서

| 비교 | CPU | GPU | TPU | NPU |
|---|---|---|---|---|
| 목적 | 범용 · 제어 | 그래픽 · 범용 병렬 | 대규모 AI 학습·추론 | 온디바이스 AI 추론 |
| 코어 | 소수 고성능 | 수천 개 단순 코어 | 행렬 연산 유닛 (MXU) | MAC 어레이 |
| 구조 | 순차 · 분기 강함 | SIMT | **시스톨릭 어레이** | 데이터플로우 |
| 정밀도 | FP64 | FP32 · FP16 | BF16 · INT8 | INT8 · INT4 |
| 유연성 | 최고 | 높음 (CUDA) | 낮음 (텐서 전용) | 낮음 |
| 전력 효율 | 낮음 | 보통 | 높음 | 매우 높음 |
| 예 | Intel · AMD | NVIDIA H100 · B200 | Google TPU | 스마트폰 AP · 자동차 |

**시스톨릭 어레이:** 데이터가 격자 속을 박자 맞춰 흘러가면서 옆 칸으로 넘기며 곱하고 더함 → 메모리 왕복 감소

**TPU를 쓰는 이유 (138회 "다·라")**
| 관점 | 설명 |
|---|---|
| 전력 효율 | 연산당 전력 낮음 (Perf/Watt) |
| 비용 | GPU 공급 부족·고가 대비 TCO 유리 |
| 특화 성능 | 행렬곱에 최적화, 불필요한 그래픽 기능 제거 |
| 확장성 | TPU Pod로 수천 칩 연결 |
| 저정밀 | BF16 · INT8로 처리량 ↑ |
| 전망 | 빅테크 자체 AI 칩(ASIC) 확산 · GPU와 공존 |

· **ASIC:** 특정 용도 전용 칩 (TPU · NPU가 여기 속함). FPGA는 회로를 다시 짤 수 있고, ASIC은 고정이지만 빠르고 효율적.

## 3-5. TPM ☆ (132 정관 1교시)

**정의:** 암호키 생성·저장과 플랫폼 무결성 측정을 수행하는 하드웨어 보안 칩
| 구성요소 | 설명 |
|---|---|
| 암호 엔진 | RSA · ECC · SHA 연산 |
| 난수 생성기 | 키 생성용 하드웨어 난수 |
| EK (Endorsement Key) | 제조 시 주입된 고유 키 |
| SRK (Storage Root Key) | 다른 키들을 보호하는 루트 키 |
| PCR | 부팅 단계별 해시 값 저장 → 무결성 측정 |
| NVRAM | 키·설정 비휘발 저장 |

- 기능: 측정 부팅 · 원격 증명(Attestation) · 봉인(Sealing) · 키 보호
- 활용: BitLocker · Windows 11 필수 (TPM 2.0)
- 하드웨어 신뢰 기반 → 안 죽는 시스템 줄기

# PART 4. 이름표

| 이름 | 한 줄 |
|---|---|
| 폴락의 법칙 | 코어를 2배 키우면 성능은 √2배만 증가 → 멀티코어로 전환한 이유 |
| RISC-V | 오픈소스 RISC 명령어 집합(ISA), 라이선스 무료, 확장 가능 |
| RISC vs CISC | 단순 명령어·파이프라인 유리 vs 복잡 명령어·코드 짧음 |
| NVLink | NVIDIA GPU 간 고속 직접 연결 |
| FPGA vs ASIC | 재구성 가능·개발 빠름 vs 고정·고성능·저전력 |
