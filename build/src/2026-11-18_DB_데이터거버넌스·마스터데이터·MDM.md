## Ⅱ. 개념 이해 및 비유
### 1. 데이터 거버넌스
영업팀·재무팀·고객센터가 각자 고객번호나 주소 형식을 다르게 관리하고, 누가 고칠 권한이 있는지도 불분명한 상황을 가정. 전사에서 **데이터 정책·표준·조직·역할·책임·업무 절차**를 정해 데이터의 품질·보안·활용성을 확보하는 관리체계가 데이터 거버넌스.

### 2. 마스터 데이터
쇼핑몰에서 `홍길동(고객)`과 `노트북(상품)`은 여러 업무·거래에서 공통으로 참조하는 **기준정보**. 반면 `11월 18일 노트북 2대 주문`은 사건/거래를 기록한 **트랜잭션 데이터**. 국가코드·통화코드처럼 분류 기준으로 사용하는 값은 **참조 데이터**.

### 3. MDM
CRM·고객센터·배송 시스템에 동일 고객의 이름·주소가 다르게 존재할 때, 데이터 수집→표준화→식별·매칭→병합/대표값 선정→검증→배포·동기화로 **신뢰할 수 있는 마스터 데이터(골든 레코드)**를 확보·유지. 대표값은 임의 또는 단순 최신값으로 정하는 게 아니라 출처·품질·업무 규칙을 활용.

### 4. 사용자 질문 및 해결
- `데이터 오너는 무슨 역할인지 몰라` → Owner: 책임·결정·승인 / Steward: 품질·표준 실무 / Custodian: 저장·보안·기술 운영. 설명 직후 Steward 사례 정답.
- `거버넌스와 MDM의 차이` → 거버넌스는 **전사적 관리 기준과 통제**; MDM은 그 기준을 **마스터 데이터에 적용하여 관리하는 구체적 체계**.
- `구축 방법이 제일 중요한가?` → 아니며 구성요소·구축 고려사항이 우선임을 설명·정정.
- `MDM 구성요소 이미지에 마스터 데이터가 없네?` → **관리 대상인 마스터 데이터**와 **관리 기능인 MDM**을 명시적으로 구분하도록 구성도 수정.
- `거버넌스는 어딨어?` → **MDM을 포함한 데이터 관리 전반을 감싸는 상위 관리체계**로 구성도 재수정. 물리적 시스템이 아니라 정책·조직·책임·통제 범위임을 설명.

## Ⅲ. 기술사 답안 핵심

### 1. 정의
- **데이터 거버넌스**: 조직 데이터의 **품질·보안·활용성 확보**를 위해 정책·표준·조직·책임·프로세스를 수립하고 통제하는 **관리체계**.
- **마스터 데이터**: 조직의 여러 시스템과 프로세스에서 공통으로 활용하는 고객·상품·조직 등의 **핵심 기준 데이터**.
- **MDM (Master Data Management)**: 조직 내 핵심 마스터 데이터의 **정합성·일관성 확보**를 위해 데이터를 통합·정제·표준화하고 공유하는 **관리체계**.
- **골든 레코드(Golden Record)**: 복수 원천의 동일 업무 객체를 매칭·정제·병합하고 신뢰할 수 있는 속성값을 선정하여 만든 대표 기준 레코드.

### 2. 세 개념의 통합 논리 구성도
```text

│ 데이터 거버넌스 (전체를 관리하는 정책·표준·조직·책임·통제)  │
│   ┌─────────────────────────────────────────────────┐   │
│   │ 원천 시스템: CRM · ERP · 업무시스템                │   │
│   │ 마스터 데이터: 고객 · 상품 · 공급업체 · 조직         │   │
│   └─────────────────────────────────────────────────┘   │
│                         │ 수집·연계                      │
│                         ▼                              │
│   ┌─────────────────────────────────────────────────┐   │
│   │ MDM (마스터 데이터 관리체계)                      │   │
│   │ 품질·표준화 / 식별·매칭·병합 / 검증·승인           │   │
│   │ [마스터 데이터 저장소 · 골든 레코드]              │   │
│   │ 배포·동기화 / 권한·변경·이력관리                  │   │
│   └─────────────────────────────────────────────────┘   │

```

| 정책·원칙 | 전사 데이터 관리 방향과 규정 | 정책, 규정 준수 |
| 표준 | 명칭·코드·형식·데이터 모델 통일 | 표준화, 일관성 |

### 4. 마스터 데이터의 필요성과 타 데이터 비교

### 6. 대표적인 MDM 처리 흐름
**수집·연계 → 정제·표준화 → 식별·매칭 → 병합·골든 레코드 생성 → 검증·승인 → 배포·동기화 및 모니터링**.
- **Survivorship Rule**: 출처·신뢰도·최신성·업무 정책 등으로 속성별 대표값을 선정하는 규칙.
- 매칭은 같은 실체인지 판단하는 기능, 병합은 중복값/레코드를 조합·통합하는 기능.

## Ⅴ. 실제 인출 및 평가
※ 아래 발화는 실제 사용자가 말한 내용. AI 설명이나 예시를 학생의 자력 인출로 간주하지 않음.

1. **데이터 거버넌스 정의**
   - 질문: 데이터 거버넌스란 무엇인가?
   - 학생: `조직의 데이터를 안전하고 가지있게 관리하기위한 원칙, 조직, 프로세스를 관리하기위한 관리체계`
   - 판정: **부분 정답**. 원칙·조직·프로세스 중심은 맞음. 데이터 품질·보안·활용성, 정책·표준·역할·책임, 수립·통제를 보강.
2. **Data Owner**
   - 질문: 데이터 오너는 무슨 역할?
   - 학생: `몰라`
   - 판정: 오답/미인출. Owner 책임·의사결정·승인, Steward 품질·표준 실무, Custodian 기술 운영 설명.
   - 설명 직후 업무 사례에서 학생 `스튜어트?` → Steward 정답(직후 1문항에 한함).
3. **MDM 기능/목적**
   - 학생: `데이터를 취합하고 어떤 데이터가 맞는지 보고, 앞으로 이거쓰라고 결정해`
   - 판정: **핵심 원리 정답**. 통합·정제·정합성 검증·골든 레코드·공유로 기술사 용어 보완.
4. **데이터 거버넌스 vs MDM**
   - 학생: `데이터거버넌스는 조직의 데이터를 어떻게 관리할지 조직, 프로세스를 잡는 큰 범주고 mdm은 그 기준에 맞춰서 마스터 데이터를 관리하는 활공이야`
   - 판정: **정답**. 큰 관리체계 vs 마스터 데이터에 대한 적용의 관계 이해.
5. **MDM 구축 방식 사례 인출**
   - 기존 시스템을 그대로 유지하며 식별 연결만 → `등록형?` (정답)
   - 중앙 수집·정제·골든 레코드 → `통합형` (정답)
   - 중앙과 개별 시스템에서 함께 관리·동기화 → `공존형` (정답)
   - 중앙에서만 생성·수정 → `중앙집중형` (정답)
   - 이후 보기 없이 4유형과 특징 요청에 학생: `등록형 통합형 공존횽 중앙집중형   원본유지, 연결정보 관리,   중앙수집정제골든레코드생성   중앙과 개별시스템 동길하   중앙에서 생성 수정통제`
   - 판정: **자력 구두 인출 4/4 정답**, 최종 신뢰할 수 있는 말로 인출 근거.
6. **구성도 검토**
   - 학생이 마스터 데이터, 거버넌스가 구성도에 빠졌다고 각각 지적 → 통합 논리 구성도로 교정. 이는 **좋은 개념 검증·비판적 질문**이나, 백지 답안 작성 근거로 쓰지 않음.
7. **필사 사실**
   - 학생: `일단 옮겨 적는건 했어`
   - 판정: 자료를 보면서 옮겨 적은 활동으로 기록. **백지 암기 인출은 아님**.

**최종 확인 수준:** **2 (무자료 말로 인출 성공 부분 있음)** — 44행 토픽 대표 수준. 근거는 MDM 유형과 거버넌스/MDM 관계를 말로 인출한 것. 거버넌스 전체 주요 기능·MDM 전체 구성요소·구축 고려사항은 아직 각각 무자료 전부 인출하지 않았음. 확인 수준 3(백지 답안) 부여 금지.

## Ⅶ. Claude·GPT 인수인계
- 학생은 기본 원리를 꽤 정확히 이해하고, 구성도에 관리 대상과 거버넌스가 빠진 오류까지 발견함. **구축 방식에 지나치게 많은 시간을 사용한 AI 진행은 반성·조정**.
- 실제 좋은 인출: `거버넌스가 더 큰 범위, MDM은 기준에 맞는 마스터 데이터 관리`, MDM 구축 방식 4개와 특징 전체 무힌트 정답.
- 취약: Data Owner 역할 처음에 모름, 데이터 거버넌스 정의에서 정책·표준 누락. MDM 전체 구성요소·고려사항은 아직 완전 무자료 인출 검증 전.
- 효과적 설명: 쇼핑몰의 고객·상품 vs 주문 데이터; CRM/배송 시스템에서 같은 고객정보가 달라지는 문제; Owner/Steward/Custodian 세 역할.
- 구성도: **거버넌스는 관리 상위 영역**, **마스터 데이터는 대상**, **MDM은 그 데이터를 관리하는 체계**. 이 구분을 구성도에서 반드시 눈에 띄게 보여줄 것.
- 오늘은 학생이 필사 후 `오늘 경영 하랬는데`라고 상기한 상태이므로, **DB 계속 붙잡지 말고 IT경영 키워드 암기·인출을 진행**.
- 토픽 시트 44행 K=2/N=2026-11-18/O에 실제 인출·취약점 기록 확인. 같은 토픽 다른 회차 행은 중복 기록하지 않음.
- 암기노트 `핵심암기 모음`의 DB 아래에 핵심 정의·구성 키워드·인출 근거를 11/18 추가 검증함.
