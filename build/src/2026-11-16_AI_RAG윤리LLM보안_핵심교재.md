## Ⅰ. RAG(Retrieval-Augmented Generation)와 Fine-tuning — 🔴 최상

**교재 기출:** 137컴 1교시 「RAG와 Fine Tuning의 기본 개념과 대표 프레임워크」, 134관·135컴 1교시 「RAG」, 139관 2교시 「파인튜닝과 RAG의 개념 및 역할, RLHF 기반 학습 파이프라인과 RAFT」, 132컴 「파인튜닝」, 137컴 2교시 「sLLM」.

### 1. 사람말로 원리

- **RAG는 ‘오픈북 시험’**: LLM 머릿속 지식은 그대로 두고, **외부 문서를 찾아 펼쳐 보며** 답한다. 규정이 바뀌면 참고 문서를 업데이트.
- **Fine-tuning은 ‘반복 연습으로 습관 교정’**: 사전학습 모델에 사례를 더 학습시켜 **가중치를 바꾸는** 방식. 말투·출력 형식·전문 과업에 유리.
- **RAG도 오답은 가능**: 틀린 문서 검색, 권한 없는 문서 검색, 잘못 인용하면 환각·정보유출 위험이 남는다.

### 2. 기술사 정의

- **RAG:** 외부 지식 검색 결과를 LLM 입력에 결합하여 응답의 근거성·최신성을 높이는 **검색 증강 생성 기법**.
- **Fine-tuning:** 사전학습 모델을 특정 과업·도메인 데이터로 추가 학습하여 모델 가중치를 최적화하는 **전이학습 기법**.

### 3. RAG 기본 구성도 (그림 그대로 옮겨 그리기)

```text
[사전 준비: 인덱싱]
사내 문서/DB → 수집·정제 → 청킹(Chunking) → 임베딩 → 벡터 DB
                                                        │
[질의 시점]                                            ▼
사용자 질의 → 질의 임베딩 ───────────────────→ 유사도 검색(Top-k)
                                               │
                                               ▼
                                  검색된 근거 문서 + 사용자 질문
                                               │
                                               ▼
                                            프롬프트
                                               │
                                               ▼
                                          LLM 응답·출처
```

**구성요소 핵심 키워드:** Document Loader / Chunk / Embedding / Vector DB / Retriever / Top-k / Prompt Augmentation / Generator / Citation.

### 4. 비교표 — 반드시 6행 이상

| 구분 | RAG | Fine-tuning |
|---|---|---|
| 지식 반영 | 외부 지식 **검색 후 입력에 결합** | 학습하여 **가중치 조정** |
| 모델 변경 | 기본 모델 가중치 변경 없음 | 기본 또는 어댑터 가중치 변경 |
| 최신성 | 문서·인덱스 갱신으로 대응 | 신규 정보 반영에 추가 학습 필요 |
| 근거·환각 | 검색 출처 제시 가능, 환각 감소 도움 | 근거 출처가 자동 생성되지는 않음 |
| 비용·지연 | 인덱스 관리·검색 지연·벡터 DB | 학습 데이터·GPU 학습 비용 |
| 주 강점 | 자주 바뀌는 사내 규정·매뉴얼 | 출력 형식·업무 수행 패턴·도메인 적응 |
| 보안 | 검색 대상 문서의 **접근권한 관리** | 학습 데이터 유출·기억 위험 관리 |
| 기술 예 | LangChain·LlamaIndex, FAISS·Milvus | Hugging Face Transformers·PEFT, LoRA·QLoRA |

**헷갈림 방지:** 벡터 DB는 저장·검색 인프라이지 모델의 ‘학습 가중치’가 아니다. 둘은 대체재만이 아니라 결합 가능.

### 5. 파인튜닝 관련 필수 확장

- **Full FT:** 모델 파라미터 전체 업데이트 → 비용 큼.
- **PEFT:** 일부 파라미터 또는 별도 소규모 모듈만 학습. **LoRA**는 저랭크 행렬로 가중치 변화 근사, **QLoRA**는 양자화와 LoRA 결합.
- **Instruction Tuning:** 지시·응답 사례로 과업 지시 이행 능력 개선.
- **RLHF 전형적 흐름:** **SFT → 선호 데이터 기반 보상모델 → PPO 등 강화학습 최적화**.
- **DPO:** 명시적 보상모델과 PPO 단계 없이 선호쌍으로 직접 최적화하는 접근.
- **RAFT (Retrieval-Augmented Fine-Tuning):** 정답 문서와 방해 문서 등 검색 맥락을 활용한 파인튜닝으로, 모델이 관련 근거를 골라 답하도록 훈련.
- **sLLM 경량화:** 지식 증류 / 양자화 / 가지치기. **LoRA는 주로 효율적 적응·파인튜닝 기법**으로, 경량화된 모델 배포와 결합할 수 있으나 모델 압축 자체와 구별.

### 6. 필수 암기

**반드시:** RAG 4단계 **인덱싱–검색–증강–생성**, FT = **가중치 변경**, 비교표 6행, RLHF 3단계, RAFT = RAG+FT.

**1교시 연습문제(교재 표기):** 「RAG와 Fine Tuning의 기본 개념과 대표 프레임워크」

**인출 질문 — 힌트 없이 한 문제씩**
1. RAG와 Fine-tuning의 차이를 실제 기업 문서 검색 사례로 설명하라.
2. RAG의 정의, 4단계 흐름과 구성요소를 말하라.
3. 6행 비교표를 자료 없이 채우라.
4. RLHF와 RAFT를 구분하라.

## Ⅱ. Advanced RAG와 Modular RAG — 🔴 최상

**교재 기출:** 139관 1교시 「Advanced RAG와 Modular RAG」.

### 1. 사람말로 원리

- **Naive RAG:** 서류를 단순 검색해서 LLM에 전달. 검색이 엉뚱하면 답도 흔들림.
- **Advanced RAG:** *기존 일자형 검색 흐름은 유지하면서* 질문을 고치고, 여러 방식으로 검색하고, 검색 결과를 다시 고르는 **정교한 검색 파이프라인**.
- **Modular RAG:** 검색·메모리·라우팅·판단 모듈을 **레고처럼 조합**, 질문에 따라 반복·우회·분기하는 **유연한 아키텍처**.

### 2. 기술사 정의

- **Advanced RAG:** 검색 전·중·후 최적화 기법을 적용하여 검색 정확도와 생성 답변 품질을 개선한 **고도화된 RAG 기법**.
- **Modular RAG:** 검색·라우팅·메모리·생성 기능을 모듈화해 과업에 따라 동적으로 조합하는 **유연한 RAG 아키텍처**.

### 3. 구성도와 차이

```text
Naive    : 질문 → 검색 → 근거 붙이기 → 생성

Advanced : 질문 → [질의 재작성] → [BM25 + Vector Hybrid 검색]
              → [재순위(Re-ranking)·압축] → 생성

Modular  : 질문 → [라우터] ─┬→ [검색 모듈] ─┐
                            ├→ [메모리] ────┤→ [평가·생성]
                            └→ [도구/예측] ─┘      │
                                  ▲──────── 재검색·반복 ─┘
```

| 구분 | Advanced RAG | Modular RAG |
|---|---|---|
| 구조 | 순차 파이프라인 최적화 | 기능별 모듈 조합 |
| 흐름 | 검색 전 → 검색 → 검색 후 | 조건 분기·반복·라우팅 |
| 핵심 기술 | Query Rewriting, HyDE | Router, Memory, Fusion |
| 검색 보강 | Hybrid Search, Re-ranking | 과업별 복수 검색기 선택 |
| 유연성 | 비교적 낮음 | 비교적 높음 |
| 복잡도 | 중간 | 높은 설계·운영 복잡도 |
| 활용 | 단일 도메인 검색 QA | 복합 업무·다중 출처·Agentic RAG |

**개념 정확성 메모:** Advanced RAG와 Modular RAG는 실무에서 엄격히 배타적인 분류가 아님. 모듈형 구조 안에 Advanced 검색 최적화를 함께 적용할 수 있다.

### 4. 용어 체크

- **BM25:** 키워드 기반 문서 관련도 점수.
- **Dense Vector Retrieval:** 임베딩 의미 유사도 검색.
- **Hybrid Search:** 키워드·의미 검색 결합.
- **Re-ranking:** 1차 후보를 더 정밀한 모델로 재정렬.
- **HyDE:** 가상의 답변/문서를 생성해 검색 단서로 사용.
- **Self-RAG:** 검색 필요성을 판단하거나 결과를 평가하며 생성하는 접근.

**필수 한 줄:** **Advanced는 '앞뒤 검색 품질 개선', Modular는 '모듈 조합과 분기'.**

**1교시 연습문제:** 「Advanced RAG와 Modular RAG를 비교 설명하시오.」

## Ⅲ. 인공지능 윤리기준·AI 윤리·AI 거버넌스 — 🔴 최상

**교재 기출:** 136관 4교시 「3대 기본원칙과 10대 핵심요건 + 생성형 AI 역기능」, 129관 1교시 「인공지능 윤리기준」, 131관 2교시 「AI 윤리 및 AI 거버넌스」, 137관 1교시 「AI 거버넌스」.

### 1. 사람말로 원리

- **AI 윤리:** AI가 사람을 해치거나 차별하지 않도록 지켜야 할 **가치·행동 기준**.
- **AI 거버넌스:** '좋은 AI 만들자'라는 선언을 실제로 지키도록 **누가 승인·감사·책임지고, 어떤 절차로 관리할지 정하는 운영 체계**.
- 기억법: **윤리 = 무엇이 옳은가 / 거버넌스 = 조직이 어떻게 지속적으로 지킬 것인가**.

### 2. 2020년 「인공지능 윤리기준」 정리

**최고 가치 = 인간성(Humanity)**

**3대 기본원칙** — *교재의 신규 두음 후보* `인·공·합`
1. 인간 존엄성
2. 사회의 공공선
3. 기술의 합목적성

**10대 핵심요건** — *교재의 신규 두음 후보* `인·프·다·침·공 / 연·데·책·안·투`

| 앞 5개 | 뒤 5개 |
|---|---|
| 인권 보장 | 연대성 |
| 프라이버시 보호 | 데이터 관리 |
| 다양성 존중 | 책임성 |
| 침해 금지 | 안전성 |
| 공공성 | 투명성 |

> 주의: 교재는 별도로 '2026 개정판의 3대 가치·7대 원칙'을 소개함. **문제가 '3대 기본원칙·10대 핵심요건'이면 위 2020년 기준으로 답해야 함.** 개정판의 공식 명칭·최신 적용 범위는 원문 대조 후 별도 확인할 것.

### 3. AI 거버넌스 구성도

```text
[사회·법 계층]   법규·규제 준수·사회적 책임 (국내 AI 기본법 등)
        ▲
[윤리 계층]      윤리 원칙·정책·위원회·책임 소재
        ▲
[기술 계층]      XAI·편향 점검·감사 로그·보안·모니터링
```

**교재의 신규 두음 후보:** `기·윤·사` = 기술 → 윤리 → 사회·법.

**거버넌스 구성요소:** 원칙(Policy) · 조직(책임·위원회) · 프로세스(평가·승인·감사) · 기술 도구(XAI, 편향 탐지, 로깅).

| 구분 | AI 윤리 | AI 거버넌스 |
|---|---|---|
| 성격 | 가치·행동규범 | 관리·통제 체계 |
| 핵심 질문 | 무엇이 바람직한가 | 누가, 어떻게 책임지는가 |
| 범위 | 공정·투명·책임·인권 | 개발·도입·운영 전 생애주기 |
| 실행 주체 | 개발자·서비스 제공자 등 | 경영진·위원회·위험관리 조직 |
| 방법 | 원칙·가이드라인 | 정책·승인·평가·감사 |
| 산출물 | 윤리 준수 기준 | 책임체계·위험관리·증적 |

### 4. 생성형 AI 역기능 — 출제 요구 시만 골라 쓰기

환각·허위정보 / 딥페이크 / 저작권 침해 / 개인정보 유출 / 편향·차별 / 사이버 공격 악용 / 디지털 격차·일자리 변화.

## Ⅳ. LLM 보안 및 운영 문제 — 🔴 최상

**교재 기출:** 138컴 2교시 「가. LLM이 컴퓨터시스템 자원에 미치는 영향 / 나. OWASP LLM 주요 위협과 시스템 수준 발생 원인 / 다. 대응방안」, 136관 4교시 「OWASP Top 10 for LLM 2025」, 138관 1교시 「프롬프트 인젝션」, 137관 2교시 「MCP 보안 취약점과 대응」 등.

### 1. 사람말로 원리

LLM을 서버에 올리면 **GPU 메모리·추론시간·전력**을 많이 쓰고, 외부 자료나 도구를 연결하면 **악의적인 문서를 지시로 착각**하거나 **권한 많은 도구를 오용**할 수 있다.

서버 관점으로 기억하자:
- **자원 문제:** '긴 요청이 GPU 메모리와 계산 시간을 계속 먹는다.'
- **보안 문제:** '검색 문서에 숨겨 둔 말이 운영 명령처럼 처리된다.'
- **권한 문제:** '에이전트가 DB/메일 삭제 권한까지 있으면 사고 범위가 커진다.'

### 2. OWASP Top 10 for LLM Applications 2025 (교재 기준)

| 코드 | 위협 | 한 줄 의미 |
|---|---|---|
| LLM01 | Prompt Injection | 악성 지시로 모델 동작 조작 |
| LLM02 | Sensitive Information Disclosure | 개인정보·기밀 노출 |
| LLM03 | Supply Chain | 모델·플러그인·패키지 공급망 위험 |
| LLM04 | Data and Model Poisoning | 학습/조정 데이터·모델 오염 |
| LLM05 | Improper Output Handling | 모델 출력을 검증 없이 실행·표시 |
| LLM06 | Excessive Agency | 에이전트에 과도한 권한·자율성 |
| LLM07 | System Prompt Leakage | 시스템 지시문 유출 |
| LLM08 | Vector and Embedding Weaknesses | 벡터·임베딩·RAG 검색 취약점 |
| LLM09 | Misinformation | 그럴듯한 허위정보 |
| LLM10 | Unbounded Consumption | 과도한 토큰·연산·비용 소비 |

### 3. '가. 자원 영향' 그림

```text
장문 입력/동시 사용자 증가
       │
       ├─ KV Cache·GPU 메모리 사용 증가
       ├─ Attention·추론 연산 증가 → 지연·처리량 저하
       └─ 전력·비용 증가
                    ↓
        가용성 저하 / 자원 고갈 공격 위험
```

**핵심 용어:** GPU·VRAM / KV Cache / Context Window / Latency / Throughput / Rate Limit / Token Quota / Unbounded Consumption.

### 4. '나. 위협과 발생 원인' — 문제 요구 중심 표

| 위협 | 시스템 수준 발생 원인 | 피해 |
|---|---|---|
| 프롬프트 인젝션 | 외부 문서·입력과 신뢰된 지시 경계 혼동 | 의도하지 않은 동작 |
| 민감정보 노출 | 데이터 권한 분리·마스킹 부족 | 개인정보·기밀 유출 |
| 공급망 공격 | 외부 모델·패키지·도구 무결성 미검증 | 악성 코드·변조 |
| 과도한 에이전시 | 넓은 도구 권한·사람 승인 부재 | DB 삭제 등 위험 행위 |
| 벡터·임베딩 취약점 | 검색 권한 필터 부재·오염된 근거 | 정보유출·잘못된 생성 |
| 무제한 자원 소비 | 토큰·요청·연산 제한 부재 | 서비스 거부·비용 폭증 |

### 5. '다. 대응방안' — 시스템 실무와 연결

| 계층 | 대응 |
|---|---|
| 입력 | 입력 검증·프롬프트 경계·가드레일 |
| 출력 | 출력 검증·도구 실행 전 점검·샌드박스 |
| 권한 | 최소 권한·OAuth Scope 제한·Human-in-the-loop |
| 데이터 | 마스킹·DLP·벡터 DB 문서별 접근제어 |
| 공급망 | 모델·라이브러리 출처 검증·서명·AI-BOM |
| 가용성 | Rate Limit·Token Quota·동시성 제어 |
| 탐지·감사 | 레드팀·모니터링·로그·이상행동 경보 |

### 6. 프롬프트 인젝션과 MCP

**프롬프트 인젝션**
- 직접형: 사용자가 악성 지시를 넣음.
- 간접형: 웹페이지·이메일·RAG 문서 등의 *신뢰하지 않는 콘텐츠* 안에 악성 지시를 숨김.
- 대응: 데이터/명령의 신뢰 경계 유지, 도구 실행 권한·정책 제어, 출력·행동 검증. **단순 문자열 필터만으로 완전 차단은 어려움.**

**MCP(Model Context Protocol)**
```text
[LLM 앱/Host]
      │
   [Client] ────── [MCP Server] ── Tools / Resources / Prompts
```
- 기능: LLM 애플리케이션과 외부 도구·데이터를 연결하는 프로토콜.
- 위협: 도구 설명 오염(Tool Poisoning) / 승인 후 정의 변경(Rug Pull) / 과권한·토큰 탈취 / 가짜 서버·공급망 공격.
- 대응: 신뢰 서버 허용목록, 도구 정의 무결성 검증, 최소 권한, 사용자 승인, 샌드박스·감사 로그.

**필수 암기:** OWASP 2025 Top 10의 위협 이름·대표 원인, **KV Cache**, **자원 영향·위협·대응**의 3대 목차, **MCP Host·Client·Server**, Tool Poisoning·Rug Pull.

**2교시형 연습문제:** 「OWASP LLM 보안 위협을 중심으로 가. LLM이 컴퓨터시스템 자원에 미치는 영향, 나. 주요 위협과 시스템 수준 발생 원인, 다. 대응방안을 설명하시오.」
