## **1\. RAG와 Fine Tuning (최상)**

**기출:** 137컴 1교시 "RAG와 Fine Tuning의 기본 개념과 대표 프레임워크" / 134관·135컴 1교시 "RAG" / 139관 2교시 "파인튜닝과 RAG의 개념 및 역할, RLHF 기반 학습 파이프라인과 RAFT" / 132컴 "파인튜닝" / 137컴 2교시 "sLLM"  
**정의**

> * RAG: 외부 지식을 검색해 프롬프트에 결합하여 LLM의 환각을 줄이고 최신성을 높이는 생성 기법  
> * Fine-tuning: 사전학습 모델을 특정 도메인·과업 데이터로 추가 학습해 가중치를 조정하는 기법

**RAG 흐름(그림 재료):** ① 인덱싱(문서 수집 → 청킹 → 임베딩 → 벡터DB 저장) → ② 검색(질의 임베딩 → 유사도 검색 Top-k) → ③ 증강(검색 문서와 질의를 프롬프트로 결합) → ④ 생성(LLM 응답 \+ 출처)  
**비교표 6줄 (RAG / Fine-tuning)**

| 구분 | RAG | Fine-tuning |
| :---- | :---- | :---- |
| 지식 반영 | 외부 문서 검색(모델은 그대로) | 가중치에 내재화 |
| 최신성 | 문서만 바꾸면 즉시 반영 | 재학습 필요 |
| 근거·환각 | 출처 제시 가능, 환각 감소 | 근거 제시 어려움 |
| 비용 | 벡터DB·검색 지연 | GPU 학습 비용 |
| 강점 | 자주 바뀌는 사내 지식·규정 | 말투·형식·전문 과업 수행 |
| 보안 | 문서 접근 권한 관리 | 학습 데이터가 모델에 남음(유출 위험) |

**대표 프레임워크:** RAG \= LangChain, LlamaIndex, 벡터DB(FAISS·Milvus·Chroma·Pinecone) / FT \= Hugging Face Transformers·PEFT 라이브러리(LoRA·QLoRA)  
**파인튜닝 유형:** Full FT / PEFT(LoRA, QLoRA, Adapter, Prompt·Prefix Tuning) / Instruction Tuning / RLHF(SFT → 보상모델 → PPO) / DPO  
**RAFT:** RAG \+ FT. 정답 문서와 방해 문서를 섞어 주고 파인튜닝해서, 검색된 문서를 잘 골라 쓰는 능력을 학습시킴  
**sLLM:** 파라미터 수를 줄인 경량 LLM(온프레미스·저비용·보안). 경량화 기술 \= 지식 증류·양자화·가지치기·LoRA  
**⚠️ 헷갈림:** RAG는 모델을 안 바꾼다. 파인튜닝은 '지식 추가'보다 '행동·형식 바꾸기'에 강하다. 실무는 둘을 같이 쓴다(RAFT, 하이브리드).

## **2\. Advanced RAG와 Modular RAG 비교 (최상, 139관 1교시)**

**RAG 진화 3단계:** Naive → Advanced → Modular. Naive는 인덱싱-검색-생성의 단순 직선이라 검색 정확도가 낮고 잡음·환각이 생긴다.

> * **Advanced RAG:** 직선 흐름은 유지하고 검색 앞뒤를 최적화. 검색 전 \= 청킹 최적화·메타데이터·쿼리 재작성/확장(HyDE). 검색 중 \= 하이브리드 검색(BM25 \+ 벡터). 검색 후 \= 재순위(Re-ranking)·컨텍스트 압축  
> * **Modular RAG:** 기능을 모듈로 쪼개 교체·조합. 흐름이 비선형(라우팅·반복·조건 분기). 모듈 \= 검색·메모리·라우팅·퓨전(RAG-Fusion)·예측. 패턴 \= 반복형, 적응형(Self-RAG: 필요할 때만 검색). Agentic RAG로 이어짐

| 구분 | Advanced RAG | Modular RAG |
| :---- | :---- | :---- |
| 구조 | 선형 파이프라인 | 모듈 조합(레고) |
| 흐름 | 검색 전 → 검색 → 검색 후 순차 | 라우팅·반복·조건 분기 |
| 핵심 기법 | 쿼리 재작성, 재순위 | 라우팅, 메모리, 퓨전, Self-RAG |
| 유연성 | 낮음 | 높음 |
| 복잡도·비용 | 중간 | 높음 |
| 적용 | 단일 도메인 QA | 여러 소스·복합 업무·에이전트 |

**한 줄:** Advanced \= 파이프라인의 앞뒤를 다듬는다 / Modular \= 부품을 갈아 끼운다

## **4\. LLM 보안 및 운영 문제 (최상, 138컴 2교시)**

**기출:** 138컴 2교시 "OWASP LLM 보안 위협 중심 — 가. LLM이 컴퓨터시스템 자원에 미치는 영향 / 나. 주요 위협과 시스템 수준 발생 원인 / 다. 대응방안" / 136관 4교시 "OWASP Top 10 for LLM 2025" / 136관 2교시 "LLM 도입 시 보안 위험 3가지 이상과 대응" / 138관 1교시 "프롬프트 인젝션" / 136관 1교시 "MCP" / 137관 2교시 "MCP 보안 취약점과 대응"  
**OWASP Top 10 for LLM 2025** (LLM01\~10)

> 1. Prompt Injection (프롬프트 인젝션)  
> 2. Sensitive Information Disclosure (민감정보 노출)  
> 3. Supply Chain (공급망)  
> 4. Data and Model Poisoning (데이터·모델 오염)  
> 5. Improper Output Handling (부적절한 출력 처리)  
> 6. Excessive Agency (과도한 권한)  
> 7. System Prompt Leakage (시스템 프롬프트 유출)  
> 8. Vector and Embedding Weaknesses (벡터·임베딩 취약점, RAG)  
> 9. Misinformation (허위정보)  
> 10. Unbounded Consumption (무제한 자원 소비)

**가. 자원 영향:** GPU·메모리(KV 캐시) 대량 점유, 긴 컨텍스트일수록 메모리 급증, 추론 지연, 전력·비용 증가 → 악용하면 서비스 거부·비용 폭탄(Unbounded Consumption)  
**다. 대응:** 입력 검증·가드레일 / 출력 검증·샌드박스 실행 / 최소 권한 \+ 사람 승인(Human-in-the-loop) / 데이터 마스킹·DLP / 모델·라이브러리 공급망 검증(AI-BOM, 서명) / 토큰 쿼터·레이트 리밋 / 벡터DB 접근 제어 / 레드팀·모니터링·로깅  
**프롬프트 인젝션:** 직접형(사용자가 지시를 덮어쓰기·탈옥) / 간접형(웹페이지·문서에 숨긴 지시를 RAG·에이전트가 읽음). 대응 \= 시스템 지시와 사용자 입력 분리, 입력·출력 필터, 권한 최소화  
**MCP:** LLM과 외부 도구·데이터를 연결하는 표준 프로토콜(Anthropic, 2024.11). 구조 \= Host·Client·Server / 제공 기능 \= Tools·Resources·Prompts

> * MCP 보안 취약점: 도구 오염(도구 설명에 악성 지시), 러그풀(승인 후 도구 정의 변경), 과도한 권한·토큰 탈취, 간접 프롬프트 인젝션, 가짜·악성 서버(공급망)  
> * 대응: 신뢰 서버 화이트리스트, 도구 정의 고정·서명, 최소 권한(OAuth 범위), 사용자 승인, 샌드박스, 감사 로그

\[RAG 정의, 학원 문장\] 사용자 질의에 대해 외부 지식 저장소에서 관련 근거를 검색하고, 이를 질의와 결합하여 LLM이 답변을 생성하도록 하는 지식 증강 생성 방식. 파인튜닝과의 구분 기준 \= 가중치를 안 바꾸고 추론 시점에 비모수 지식(Non-parametric Knowledge)을 주입함. 비유: 오픈북 시험.  
\[RAG 등장 배경 4개\] 환각 / 최신성 한계(Knowledge Cutoff) / 사내 지식 부재 / 추적성(출처) 요구.  
\[RAG 그림, 오답 주의\] 사전 인덱싱(오프라인: 수집·전처리 → 청킹 → 임베딩·색인)과 질의 처리(온라인: 검색 → 증강 → 생성)를 나눠서 그려야 함. '검색 결과를 붙여 주는 기능'으로만 쓰면 감점.  
\[파인튜닝·장문 컨텍스트와 구분\] 파인튜닝 \= 가중치 갱신, 능력·문체 변경(지식 갱신엔 비효율) / 장문 컨텍스트 \= 통째로 넣음, 비용·지연 크고 중간 유실(Lost in the Middle) / RAG \= 필요한 조각만, 갱신 쉽고 출처 추적.  
\[Advanced vs Modular 비교 축\] '흐름을 잘 돌리는가(Advanced, 부분 보완)' vs '흐름을 바꿀 수 있는가(Modular, 구조 재편)'. Advanced 한계 \= 파이프라인은 여전히 선형 고정. Modular 패턴 \= Rewrite-Retrieve-Read, 반복·재귀·적응형 검색. Modular가 Agentic RAG의 구조적 전제.  
\[Agentic RAG, 9주차 1교시 13번\] 기존 RAG 한계(검색 1회만, 실패 시 복구 수단 없음, 청킹 경계 문맥 단절, 질의 유형 무관 같은 경로)에 1:1로 대응: LLM 에이전트가 질의 분해·계획, 검색 필요 여부·반복 횟수 판단, 도구 호출로 다중 소스(벡터DB·SQL·API), 자기 검증 후 재검색. 구성 \= 단일 에이전트 라우터형 / 다중 에이전트 분업형. 적용 시 \= 도구 권한 최소화, 반복 상한·시간 예산, 검색 근거 로깅.  
\[인공지능기본법, 9주차 3교시\] 2026.1.22 시행. 핵심 \= 이원 구조: 고영향 AI는 활용 영역(용도) 기준(제2조 제4호, 제33\~35조), 안전성 확보 의무는 학습 누적 연산량(규모) 기준(제32조, 10^26 FLOP 이상 \+ 최첨단 \+ 중대 영향 3요건 모두). 고영향 영역 \= 에너지·먹는물·보건의료·의료기기·원자력·생체인식 범죄수사·채용/대출 심사·교통·공공서비스·교육 평가(10개 \+ 대통령령 위임). 영역에 속해도 '생명·신체·기본권 중대 영향' 요건을 같이 충족해야 고영향. 오답 주의: EU AI Act 고위험과 같다고 쓰면 감점(한국은 금지 등급 없음, 고영향 단일 범주). 거버넌스 대응은 식별 → 조직 → 프로세스 → 증빙 4단.
