## PM 전체 체계 — PMBOK·ISO 21500·ISO 21502 연결 (2026-11-23, GPT 설명 학습)

- 핵심정의 | PMBOK=PMI가 정리한 프로젝트관리 지식체계 / ISO 21500 계열=ISO의 프로젝트·프로그램·포트폴리오 관리 표준. 'PMBOK=ISO 21500'은 아님.
- 10대 지식영역(전통적 PMBOK 6판) | 통합·범위·일정·원가·품질·자원·의사소통·리스크·조달·이해관계자. 질문: 무엇을 관리하나?
- 5대 프로세스 그룹(PMBOK 6판) | 착수·기획·실행·감시통제·종료. 질문: 어떤 성격의 관리활동인가? 시간순으로만 한 번씩 수행하는 생명주기 단계가 아니라 서로 겹치고 반복되는 프로세스 분류.
- 지식영역×프로세스 예 | WBS 작성=범위관리×기획 / 리스크 대응계획=리스크관리×기획 / 통합변경통제=통합관리×감시·통제. 개별 토픽의 '수행 절차'를 묻는 문제에 5개 그룹을 그대로 나열하면 안 됨.
- ISO 판별 필수 | ISO 21500:2012는 5개 프로세스 그룹×10개 주제 그룹 체계의 과거 지침(철회). ISO 21500:2021은 프로젝트·프로그램·포트폴리오 관리의 맥락과 개념, ISO 21502:2020은 프로젝트관리 수행 지침. 2012 구조를 최신 ISO 21500의 현행 구성으로 오기 금지.
- 삼중제약 | 범위·일정·원가 간 상호제약과 품질 균형. 무단 범위 확대(Scope Creep)·임의 과잉 제공(Gold Plating)은 추가 비용·일정·리스크를 유발할 수 있음.
- 수행 접근방식 | 예측형(초기 상세계획), 적응형(반복·증분·변화 수용), 혼합형(상황별 결합). 프로세스 그룹과 생명주기 유형은 다른 축.
- 산출물 연결 | 범위=WBS·범위기준선 / 일정=CPM·일정기준선 / 원가=예산·EVM / 자원=RACI / 리스크=리스크등록부.
- ISO 근거 | https://www.iso.org/standard/75704.html (ISO 21500:2021) / https://www.iso.org/standard/74947.html (ISO 21502:2020)

## WBS (2026-11-23, GPT, PM)

- 정의: 프로젝트 범위를 산출물 중심으로 계층적 분해하여 관리 가능한 작업패키지를 정의하는 구조(WBS). 기존 두음 '범계관산' 유지.
- 구성 | 프로젝트 → 산출물별 상위 WBS 요소 → 작업패키지(WP, 최하위 관리 단위). 통제계정(CA)은 WBS와 책임조직(OBS)의 교차점에 지정한 범위·일정·원가 통합 관리점으로 특정 최상위 레벨에 고정되지 않음. Planning Package는 상세 WP로 전개 전의 계획 단위이며 CA→PP→WP 필수 순서는 아님.
- 지식영역별 활용 | 범위: 범위기준선 수립 / 일정: WP 기반 활동 정의·기간 산정 / 원가: WP 원가추정·CA 예산집계 / 자원: 인력·장비 배정 / 품질: 산출물 품질기준·인수검증 / 리스크: WP별 위험 식별·대응 / 조달: 외주 범위·계약 명세 / 통합: 변경 영향·기준선 관리.

## Scope Creep·Gold Plating — WBS·범위관리 연결 (2026-11-23, GPT)

- 비교 | Scope Creep=정식 승인·변경통제 없이 프로젝트 범위가 점진적으로 확대되는 현상. Gold Plating=요구·승인되지 않은 기능이나 품질을 개발자가 임의로 과잉 제공하는 행위.
- 원인 | Scope Creep: 요구사항 명확화 부족·변경통제 부재·고객 요청 누적 / Gold Plating: 임의 판단·과잉서비스·명세보다 더 제공하려는 욕심.
- 영향 | 범위 이탈 → 작업량·원가 증가, 일정 지연·품질/리스크 증가 가능.
- 대응 | 요구사항·범위기준선 명확화 → 변경요청서·영향분석 → 승인/반려 → 승인사항만 반영 → 인수기준 검증. 범위기준선은 범위기술서+WBS+WBS 사전.
- WBS 연관 | WBS=승인된 산출물/작업패키지의 범위 파악. Gold Plating=정의된 범위를 넘어 임의 추가, Scope Creep=승인 없는 범위 확대.

## BCP(Business Continuity Planning) 및 DRS (2026-11-23, GPT, IT경영)

- 정의: 재해 발생 시 핵심 업무의 지속·복구 목표와 전략을 수립하는 계획(BCP). DRS는 목표 달성을 위한 IT 재해복구시스템.
- 흐름 | BIA(업무영향분석) → 허용 중단·손실 및 복구목표 설정 → 업무연속성 전략·BCP 수립 → 이를 지원하는 DRS 구축 → 훈련·개선.
- 지표 | MTD=최대 허용 중단시간 / RTO=목표 복구시간(MTD 이내) / RPO=목표 복구시점(허용 데이터 손실 범위) / MBCO=최소 업무연속성 목표.
- DRS 구축 고려 | 목표: RTO·RPO 충족 / 복구체계: Hot·Warm·Cold 등 방식 선정 / 복제: 동기·비동기 복제와 지연·정합성 / 센터: 지리적 분리·재해 상관관계 / 네트워크: 통신 경로·대역폭 / 자원: DR 용량·성능 / 검증: 모의 전환·복구훈련으로 목표 달성 확인.
- 연계 | RPO↔복제, RTO↔전환(자동 전환), 훈련으로 검증.
