# PART 2. 메모리 벽 줄기 (셀테 8번)

## 2-1. 메모리 벽 (Memory Wall) ★ (140회)

**정의:** 프로세서 연산 속도 향상에 비해 메모리 대역폭과 지연 개선이 뒤처져 발생하는 성능 병목

**발생 원인**
| 원인 | 설명 |
|---|---|
| 성능 격차 | CPU 연산 성능은 빠르게 증가, DRAM 대역폭은 완만 |
| 폰노이만 구조 | 연산과 메모리 분리, 데이터 이동 필수 |
| AI 모델 대형화 | 파라미터 수 급증, 데이터 이동량 폭증 |
| 핀 수 한계 | 칩 패키지 I/O 핀 수 제한, 대역폭 한계 |
| 용량 한계 | CPU당 메모리 채널 수 제한 |
| 전력 | 데이터 이동 에너지가 연산 에너지보다 큼 |

**해결 방향 3갈래**
| 방향 | 기술 | 한 줄 |
|---|---|---|
| 대역폭 ↑ | **HBM** | 수직 적층, 넓은 버스 |
| 용량 ↑ · 공유 | **CXL** | 메모리 확장 · 풀링 |
| 이동 ↓ | **PIM · PNM** | 메모리에서 계산 |

## 2-2. 메모리 계층 + AI 대역폭 (140회 2교시)

- 계층: 레지스터 → 캐시(SRAM) → 주기억(DRAM · **HBM**) → SSD → HDD
- **AI 시대에 대역폭이 중요한 이유:** LLM 추론은 토큰마다 가중치를 메모리에서 전부 읽어와요. 계산보다 **읽는 속도가 성능을 결정**해요 (Memory-bound).

## 2-4. CXL (Compute Express Link) ★ (129 · 136 · 140회)

**정의:** PCIe 물리계층 기반으로 CPU·가속기·메모리 간 캐시 일관성을 보장하는 고속 인터커넥트

**목적 (129회 1)**
- 메모리 용량 확장 (슬롯 한계 극복)
- 이기종 장치 간 캐시 일관성
- 메모리 풀링·공유로 자원 효율 ↑
- 개방형 표준 (Intel 주도 → 컨소시엄)

**프로토콜 3 🎵 "아캐멤" (129회 2)**
| 프로토콜 | 역할 |
|---|---|
| CXL.**io** | 장치 탐색·설정·인터럽트, PCIe와 동일 (필수) |
| CXL.**cache** | 장치가 **호스트 메모리를 캐싱** (일관성 유지) |
| CXL.**mem** | 호스트가 **장치 메모리에 접근** (Load/Store) |

**디바이스 유형 3 (129회 3)**
| 유형 | 프로토콜 | 예 |
|---|---|---|
| Type 1 | io + cache | 메모리 없는 가속기 (SmartNIC) |
| Type 2 | io + cache + mem | 자체 메모리 있는 가속기 (GPU · FPGA) |
| Type 3 | io + mem | **메모리 확장 장치** (CXL 메모리) |

🎵 **"1은 캐시, 3은 메모리, 2는 둘 다"**

**버전**
| 버전 | 기반 | 핵심 |
|---|---|---|
| 1.1 | PCIe 5.0 | 직접 연결 (1:1) |
| 2.0 | PCIe 5.0 | 스위치 · **메모리 풀링** |
| **3.0** | **PCIe 6.0 (64GT/s)** | **패브릭 · 다단 스위치 · 메모리 공유 · P2P** |

**CXL 3.0 구조 (140회)**
- 여러 호스트(CPU) ↔ CXL 스위치(다단) ↔ 메모리 풀(Type 3) · 가속기
- 핵심: 여러 호스트가 같은 메모리를 **동시에 공유**, 장치끼리 **P2P 직접 통신**, 대역폭 2배

## 2-5. PIM vs PNM ☆ (129 · 131회)

| 비교 | PIM | PNM |
|---|---|---|
| 연산 위치 | 메모리 **셀·뱅크 안** | 메모리 **옆** (베이스 다이 · 버퍼 · CXL 컨트롤러) |
| 데이터 이동 | 최소 | 적음 |

🎵 **In = 안 / Near = 옆**
