# 2026-11-19 디지털서비스 — 클라우드·에이전틱AI·AIDC (피지컬AI·서버리스 포함)

## Ⅰ. 학습 개요
- 날짜: 2026-11-19(목), 한국시간. 방식: GPT 대화 중 구술 인출·질의응답. 백지 독립 작성 없음.
- 전체 학습: 클라우드 NIST 5특징·서비스/배포 모델, 에이전틱 AI, MAS, MCP/A2A, 피지컬 AI, 서버리스, AIDC·All-Reduce, CXL vs RDMA 비교(기존 연결 토픽 복습).
- 중요도(교재_20261119): 클라우드·Agentic AI·MAS·Physical AI 최상, 서버리스·AIDC·All-Reduce 상. 신규 토픽 추가하지 않는 날. 교재가 지정한 '데이터 병렬화 vs 모델 병렬화'는 오늘 GPT 대화에서 완성된 비교를 독립 인출하지 못함.

## Ⅱ. 개념 이해와 실제 질문
### 클라우드
- NIST 다섯 특성 네 개를 무힌트로 '광범위한 네트워크(접근), 주문형 셀프서비스, 신속한 탄력성, 측정서비스'라고 말하고 남은 '자원 풀링'을 의미 힌트(여러 사용자가 자원을 공유·동적할당)로 인출. 4/5 무힌트 + 1/5 힌트. 서비스 IaaS/PaaS/SaaS, 배포 Public/Private/Hybrid/Community는 과거 학습을 토대로 회상한 문답 내용이며 이 대화 새 독립 인출은 불확실.
### 에이전틱 AI·MAS
- '목적을 가지고 계획을 하고 도구를 가지고 실행하고 성찰하고 계획하거나 완료해'라며 동작 흐름을 독립 구술. 모델/시스템과 에이전트의 차이 질문. 성찰은 선택적 설계 요소임을 정확히 교정.
- 싱글=혼자, MAS=여럿 함께 역할분담한다는 원리 독립 인출(말투: '힘을 합쳐서 함께 적을 물리친느거야'). MAS에는 협력뿐 아니라 경쟁·협상도 가능.
- A2A='에이전트끼리 통신', MCP='도구 호출시 사용하는 통신' 독립 구분. 공유 폴더/게시판으로도 MAS 구현 가능하며 A2A 필수 아님. 학생이 GPT·Claude는 '그냥 LLM 아닌가'라고 정확한 구분 질문함. 실제 공동장부 협업 자체가 반드시 MAS인 것은 아님.
### 피지컬 AI
- '보고! 판단하고! → 예측하고! → 미세제어! → 액션 → 피드백!' 자력 인출. 기본 5단계=인지→판단/계획→저수준 제어→행동→피드백. '예측'은 World Model 활용 시 가능하나 모든 시스템 필수 독립 단계 아님.
- VLA, World Model, PID, Actuator 연달아 자력 이름을 언급. Sim-to-Real 차이 해결법 '도메인랜덤화' 무힌트 정확. 로봇 위험시 E-STOP 무힌트 인출. Safety Interlock/Fail-safe와 AI 판단 독립 안전제어 설명.
### 서버리스
- FaaS='Funtion as a service faas' (Function 철자 교정). 운영 편의성·유연/자동확장, 콜드스타트·벤더 종속성 장단점 각각 2/2 무힌트로 두 차례 가까이 독립 인출. '추운시작'을 콜드스타트 뜻과 연결. 사용자는 난방비를 아끼다 추워서 힘들다고 말함.
- Cold Start, 미리 워밍/Provisioned Concurrency 예시 설명했지만 해당 개선기술 독립 인출 없음. 서버리스 상태 관리/실행 시간 제한/관측성은 11/19 밤 Claude가 별도 문답(그 기록과 중복하지 말 것).
### AIDC·All-Reduce
- 처음 '학습 데이터를 나눠 시간 단축'이라고 답함 → 데이터 병렬화의 목적이지 All-Reduce의 직접 목적은 아님. 같은 모델의 가중치 A에 대해 여러 GPU가 서로 다른 데이터로 계산한 기울기를 집계·동기화해야 함을 예시로 학습.
- `GPU1 [1,2], GPU2 [3,4]`이면 같은 위치의 합 `A=4,B=6`; Reduce-Scatter에서 GPU별 합산 담당 조각 보유, All-Gather에서 조각 공유하여 모두 [4,6] 보유. 학생 '왜 1+3을 해?' 질문으로 기울기 인덱스 뜻이 불명확하다는 점을 지적. 같은 가중치의 기울기끼리 합산한다는 설명 후 '후자?'로 이해 확인.
- `All-Gather`는 명칭 구술 성공(학습 직후 반복). `Reduce-Scatter`는 여러 회에 `all_st...?`, `all-scatter?`, `첫단계면 분산 학습`이라고 답해 명칭 독립 인출 실패. 영어 Reduce=합산/집계, Scatter=분산, Gather=수집을 반복 교정. 'Reduce' 뜻 질문에 '학습?' 오답, 'Scatter' 의미 '나눠 가진다' 정답.
- AIDC 고속통신 이유: GPU 간 기울기 주고받는 통신이 많이 발생한다는 설명 자력. NVLink(서버 내/가속기 간 고속연결), InfiniBand(서버 간 네트워크)를 각각 무힌트 명칭 인출 성공. RDMA 정답 질문에 'DMA...? CXL?' 오답, 후속 DMA vs RDMA 비교에서 DMA=CPU 덜 개입하고 메모리 전송, RDMA=GPU 메모리로?라고 추정 → GPU 전용 아님, 원격 서버 메모리 접근이라고 교정. R=Remote(원격) 정확 인출.
- CXL vs RDMA 차이를 여러 번 질문, 구분 설명: CXL은 PCIe 기반 캐시 일관성/메모리 확장·공유 인터커넥트; RDMA는 NIC·네트워크 통한 원격 메모리 접근. Type2는 자체 메모리 탑재 가속기(CXL.cache·CXL.mem), Type3는 메모리 확장기. Type2 vs RDMA 개념 질문 후 '2' 선택(직전 비교표 제공, 장기 인출 증거 아님).
- AIDC 냉각: 수랭/액체 냉각, 액침 냉각은 무힌트 인출. 절연성 냉각액(광유/합성유), 누수 시 합선·부식, 인화점/자연발화온도 차이 질문. 사용자는 'GPU 과열뿐 아니라 건물 외부 화재 시 냉각액이 연료가 돼 위험하지 않나'고 예리하게 질문함 → 냉각액의 화재 특성, 누출·방화구획·소화 대책 검토 필요. SK 액침 냉각 사업 기사 떠올림.
- GPU 8개→16개도 속도 2배 안 되는 이유를 설명받음: All-Reduce 통신, 동기화, I/O 병목, 병렬화 불가능한 부분(암달의 법칙). GPU 인터커넥트 NVLink와 InfiniBand 이름은 독립 인출 성공.

## Ⅲ. 기술사 답안 핵심
### 클라우드·에이전틱 AI
- NIST 5 특징: 주문형 셀프서비스 / 광범위 네트워크 접근 / 자원 풀링 / 신속한 탄력성 / 측정 서비스.
- Agentic AI: 목표→계획→도구 실행→결과 평가→재계획/완료. MAS: 복수 에이전트의 역할 분담·상호작용. A2A=에이전트 간 표준 메시지/작업 교환; MCP=외부 도구/데이터 연결.
### 피지컬 AI
- 동작: 인지(센서/VLA 등)→판단·계획(World Model 등)→저수준 제어(PID)→행동(Actuator)→피드백. 현실 일반화: Sim-to-Real / Domain Randomization. 안전: 독립 안전 제어·E-Stop·Interlock·Fail-safe.
### 서버리스
- 서버 관리 추상화, 이벤트 기반 함수 실행 FaaS. 장점: 운영 부담 감소·Auto Scaling·사용량 기반 과금. 단점: Cold Start·Vendor Lock-in·상태 관리·시간 제한·관측성 어려움. 한계 전체 5개는 별도 밤 Claude 기록과 구분 필요.
### AIDC/All-Reduce
- AIDC = AI 학습·추론에 필요한 GPU, 고속 네트워크, 고성능 스토리지, 전력/냉각과 자원 관리 인프라 최적화 데이터센터.
- 데이터 병렬화: 동일 모델을 GPU마다 두고 데이터 배치를 나눔, 기울기 집계 필요. 모델 병렬화: 모델/계층/텐서를 GPU에 나눠 배치. 비교표 전체의 오늘 GPT 독립 인출 없음.
- Ring All-Reduce = Reduce-Scatter(조각별 합산·분산) → All-Gather(합산 조각 수집·공유). NVLink/NVSwitch=GPU 고대역폭 연결, InfiniBand/RoCE/RDMA=원격 고속 통신. CXL Type2는 자체 메모리 가속기 및 캐시 일관성, CXL Type3는 메모리 확장.
- 냉각: 직접 액체 냉각(DLC) vs 절연성 냉각액 액침 냉각; 화재 위험 평가·누출 차단·방화구획·적합한 소화 시스템.
