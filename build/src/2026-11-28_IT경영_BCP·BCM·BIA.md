# BCM · BCP · BIA · DRS 통합 정리

2026-11-28 | 관리 → 분석 → 전략 → 계획 → 시스템 구축 → 검증

## 1. 전체 개념 및 관계

```text
┌──────── BCM 업무연속성관리 ────────┐
│ 정책·목표·조직 (책임·권한·예산)    │
│               ↓                    │
│ BIA 업무영향분석 + RA 위험평가     │
│ 복구목표·우선순위 / 위협·취약성    │
│               ↓                    │
│ 연속성 전략 (대체시설·인력·DRS 선정)│
│               ↓                    │
│ BCP 업무연속성계획                 │
│  └ DRP IT 시스템 복구절차          │
│               ↓                    │
│ DRS 재해복구시스템 (구축·운영)     │
│               ↓                    │
│ 모의훈련·평가·지속적 개선          │
└────────────────────────────────────┘
```

### 시험용 정의

| 구분 | 정의 |
|---|---|
| BCM | 재해 시 핵심업무 연속성 확보를 위한 전사적 관리체계 |
| BIA | 업무 중단 영향을 분석하여 복구 우선순위와 목표를 도출하는 기법 |
| BCP | 재해 시 핵심업무의 지속 및 복구를 위한 사전 대응계획 |
| DRP | 재해로 중단된 정보시스템의 복구를 위한 실행계획 |
| DRS | 재해 시 정보시스템의 신속한 복구를 위한 대체 시스템 |

## 2. BCM (Business Continuity Management)

### 가. 쉽게 이해하기
회사에서 재해가 발생해도 업무가 중단되지 않도록 평상시부터 정책, 조직, 계획, 시스템, 훈련을 지속적으로 관리하는 것.

### 나. BCM 구성도 — PDCA

```text
┌─ Plan ──────────┐     ┌─ Do ────────────┐
│ 정책·목표 수립  │ ──→ │ BIA·RA          │
│ 조직·책임 정의  │     │ 전략·BCP 수립   │
│ 자원 확보 계획  │     │ 구축·훈련       │
└─────────────────┘     └─────────────────┘
        ↑                       ↓
┌─ Act ───────────┐     ┌─ Check ─────────┐
│ 시정조치        │ ←── │ 모니터링        │
│ 지속적 개선     │     │ 내부심사·평가   │
└─────────────────┘     └─────────────────┘
```

### 다. 핵심 구성요소

| 구분 | 구성요소 | 설명 |
|---|---|---|
| 계획 | 정책·목표 | 관리 방향 및 기준 |
| 계획 | 조직·책임 | 역할·권한·책임 정의 |
| 실행 | BIA·RA | 영향도 및 위험 분석 |
| 실행 | 전략·BCP | 연속성 확보 방안 |
| 평가 | 심사·모니터링 | 관리체계 효과성 검증 |
| 개선 | 시정조치 | 문제 보완 및 개선 |

관련 표준: ISO 22301(BCMS, 업무연속성관리시스템).

**암기 핵심: BCM은 PDCA 기반 전사적 관리체계.**

## 3. BIA (Business Impact Analysis)

### 가. 쉽게 이해하기
은행 전산센터에 불이 났다고 가정해 보자. 인터넷뱅킹, 계좌이체, 급여관리, 사내메일이 모두 중단됐어. 전부 동시에 살릴 수 없다면 어떤 업무부터 살려야 하는지, 얼마나 오래 중단되어도 되는지 판단해야겠지? 이게 BIA야.

### 나. BIA 수행 절차

```text
업무 식별       : 업무·시스템·의존관계 파악
    ↓
업무영향 분석   : 재무적·비재무적 피해 분석
    ↓
핵심업무 선정   : 중요도·복구 우선순위
    ↓
복구목표 설정   : MTPD·RTO·RPO·MBCO
    ↓
필요자원 산정   : 인력·시설·시스템·데이터
```

### 다. BIA 핵심 복구지표 구성도

```text
복구 가능          재해 발생        목표 복구       허용 한계
데이터 시점           │                │                │
    │←── RPO ───────→│←──── RTO ─────→│                │
────●────────────────●────────────────●────────────────●──→ 시간
                     │←───────── MTPD ────────────────→│
```

| 지표 | 의미 | 쉽게 외우기 |
|---|---|---|
| MTPD | 최대 허용 중단기간 | 얼마나 버틸까? |
| RTO | 목표 복구시간 | 언제까지 살릴까? |
| RPO | 목표 복구시점 | 얼마나 잃어도 될까? |
| MBCO | 최소 업무연속성 목표 | 어느 수준까지 살릴까? |

```text
업무 수준
100% ──────┐                              ┌──── 정상화
           │                    ┌─────────┘
MBCO ──────┼──────────┌─────────┘──────────────
           │          │
   0       └──────────┘
           재해       RTO                      → 시간
```

MBCO는 전체 업무의 완전한 정상화가 아니라 최소한 확보해야 하는 업무 수준.

### 라. BIA와 RA 차이

| 구분 | BIA | RA |
|---|---|---|
| 관점 | 업무 중단 영향 | 위험 발생 가능성과 영향 |
| 질문 | 중단되면 얼마나 피해를 볼까? | 어떤 위험이 발생할까? |
| 분석 | 재무·비재무 피해 | 위협·취약성·위험도 |
| 결과 | 복구 우선순위·목표 | 위험 대응방안 |

BIA는 복구목표를 정하고, RA는 위험 대응방안을 결정하는 근거를 제공한다.

## 4. BCP (Business Continuity Plan)

### 가. 쉽게 이해하기
실제로 재해가 발생했을 때 당황하지 않고 누가, 언제, 무엇을, 어떻게 수행해야 하는지 미리 만들어 놓은 행동계획.

### 나. BCP 수립 절차

```text
① 프로젝트 계획       : 추진조직·범위·목표
          ↓
② BIA 및 RA            : 업무영향·위험·복구목표
          ↓
③ 업무연속성 전략 수립 : DRS 유형·대체 사업장·인력 선정
          ↓
④ BCP 설계 및 개발     : 대응·복구 절차 작성, DRS 구축
          ↓
⑤ 테스트 및 모의훈련   : 재해 시나리오·DR 전환·목표 검증
          ↓
⑥ 유지관리             : 계획서 현행화·개선
```

[새로, 미확정] 두음: 계분전설훈유 — 계획 → 분석 → 전략 → 설계 → 훈련 → 유지

### 다. BCP 계획서 구성요소
수립 절차와 계획서 구성요소는 구분해야 해.

| 구분 | 구성요소 | 내용 |
|---|---|---|
| 조직 | 비상대응조직 | 역할 및 책임 |
| 발동 | 발동 기준 | 재해 판단 및 선언 |
| 연락 | 비상연락망 | 보고·전파 체계 |
| 대응 | 초기 대응절차 | 피해 확산 방지 |
| 지속 | 대체업무 절차 | 대체시설·인력 운영 |
| 복구 | DRP | 시스템 및 데이터 복구 |
| 정상화 | 복귀 절차 | 정상 업무 전환 |

### 라. BCP 검증 방안

| 유형 | 설명 |
|---|---|
| 체크리스트 검토 | 계획서 항목 및 누락 확인 |
| 워크스루 | 담당자별 대응절차 검토 |
| 시뮬레이션 | 가상 재해 시나리오 훈련 |
| 병행 테스트 | 주센터 운영 중 DR센터 검증 |
| 전면 중단 테스트 | 주센터 중단 후 실제 전환 |

## 5. DRS (Disaster Recovery System)

### 가. 쉽게 이해하기
BCP가 복구하기 위한 행동계획이라면 DRS는 실제로 정보시스템을 복구할 수 있도록 구축해 놓은 기술적 인프라.

### 나. DRS 기본 구성도

```text
                  [사용자]
                     │
          ┌──────────┴──────────┐
          ↓                     ↓ Failover
┌──── 주센터 ────┐      ┌──── DR센터 ────┐
│ [네트워크]     │      │ [네트워크]      │
│      ↓         │      │      ↓          │
│ [서버·DB]      │      │ [서버·DB]       │
│      ↓         │      │      ↓          │
│ [스토리지] ────┼─────→│ [스토리지]      │
└────────────────┘ 복제 └─────────────────┘
```

### 다. DRS 구축 유형별 구성도

**① Mirror Site — 실시간 운영**

```text
┌── 주센터 ──┐          ┌── DR센터 ──┐
│ [서버 운영]│          │ [서버 운영]│
│     ↓      │          │     ↓      │
│ [데이터] ──┼─────────→│ [데이터]   │
└────────────┘ 실시간복제└────────────┘
```
양 센터 운영 · 실시간 복제 · 즉시 전환 수준.

**② Hot Site — 가동 대기**

```text
┌── 주센터 ──┐          ┌── DR센터 ──┐
│ [서버 운영]│          │ [서버 대기]│
│     ↓      │          │     ↓      │
│ [데이터] ──┼─────────→│ [데이터]   │
└────────────┘ 데이터복제└────────────┘
```
서버·데이터 준비 완료 · 장애 시 서비스 활성화.

**③ Warm Site — 일부 시스템 준비**

```text
┌── 주센터 ──┐          ┌── DR센터 ──┐
│ [서버 운영]│          │ [일부 서버]│
│     ↓      │          │     ⋮      │
│ [데이터] ──┼ - - - - →│ [백업자료] │
└────────────┘ 주기백업 └────────────┘
```
일부 장비 확보 · 추가 구성 및 데이터 복원.

**④ Cold Site — 기반시설만 확보**

```text
┌── 주센터 ──┐          ┌── DR센터 ──┐
│ [서버 운영]│          │ 공간·전력  │
│     ↓      │          │ 통신시설   │
│ [데이터]   │ - - - - →│ 장비 미설치│
└────────────┘ 재해시구축└────────────┘
```
공간·전력·통신 확보 · 재해 후 장비 설치 및 복원.

### 라. DRS 구축 유형 비교

| 구분 | Mirror | Hot | Warm | Cold |
|---|---|---|---|---|
| 서버 | 운영 | 대기 | 일부 | 미설치 |
| 데이터 | 실시간 | 복제 | 백업 중심 | 별도 백업 |
| 사전 준비 | 전체 | 전체 | 일부 | 기반시설 |
| 사후 작업 | 전환 | 활성화 | 구성·복원 | 설치·복원 |
| RTO | 매우 짧음 | 짧음 | 중간 | 김 |
| RPO | 매우 짧음 | 짧음 | 상대적 김 | 상대적 김 |
| 비용 | 매우 높음 | 높음 | 중간 | 낮음 |

**운영 → 대기 → 일부 → 공간**

구성도는 주센터를 똑같이 그리고 DR센터 부분만 변경하면 돼. 복구시간과 데이터 복제 주기는 실제 구축 방식에 따라 달라질 수 있으므로 절대적인 수치로 외우지 말자.

### 마. 동기 복제와 비동기 복제

**동기 복제(Synchronous)**

```text
애플리케이션        주센터            DR센터
     │                │                │
     │── 쓰기 요청 ──→│                │
     │                │── 데이터복제 ─→│
     │                │←─ 복제완료 ACK─│
     │←─ 쓰기완료 ACK─│                │
```
DR센터 복제 완료를 확인하고 쓰기 완료를 응답.

**비동기 복제(Asynchronous)**

```text
애플리케이션        주센터            DR센터
     │                │                │
     │── 쓰기 요청 ──→│                │
     │←─ 쓰기완료 ACK─│                │
     │                │                │
     │                │- - 데이터복제 →│
```
주센터 쓰기 완료 후 DR센터에 비동기적으로 복제.

| 구분 | 동기 복제 | 비동기 복제 |
|---|---|---|
| 응답 | 원격 복제 확인 후 | 로컬 저장 완료 후 |
| RPO | 0에 가까움 | 데이터 손실 가능 |
| 지연 | 상대적으로 큼 | 상대적으로 작음 |
| 거리 | 지연에 민감 | 원거리 유리 |
| 특징 | 데이터 보호 우수 | 성능·거리 유리 |

### 바. DRS는 언제 구축하는가?

| BCP 단계 | DRS 관련 수행 내용 |
|---|---|
| BIA | RTO·RPO 결정 |
| 전략 수립 | Mirror·Hot·Warm·Cold 선정 |
| 설계 및 개발 | DR센터 설계 및 시스템 구축 |
| 테스트 및 훈련 | Failover·Failback 검증 |
| 유지관리 | 데이터 복제·구성 현행화 |

## 6. BCM과 BCP 헷갈리는 부분

둘의 절차가 비슷한 것은 실제로 포함 관계이기 때문이야. 억지로 서로 다른 절차를 외울 필요가 없어.

| 비교 | BCM | BCP |
|---|---|---|
| 관점 | 전사적 관리 | 실행계획 |
| 정책·계획 | 관리 기준 수립 | 대응절차 수립 |
| 조직 | 관리 책임·권한 | 대응·복구 역할 |
| 평가 | 관리체계 효과성 | 복구계획 실효성 |
| 개선 | 관리체계 개선 | 계획서 현행화 |
| 암기 틀 | PDCA | 계분전설훈유(미확정) |

은행을 예로 들면 BCM은 경영진이 관리 책임자와 예산, 관리 기준을 정하는 것이고, BCP는 장애 발생 시 서버 담당자가 어떤 순서로 DR센터를 가동할지 정하는 것이야.

## 7. 시험 직전 핵심암기 모음

- **BCM — 관리:** PDCA. 정책·조직 → 분석·전략·계획 → 평가 → 개선.
- **BCP — 계획:** 계획 → 분석 → 전략 → 설계 → 훈련 → 유지. [새로, 미확정] 계분전설훈유.
- **BIA — 분석:** 업무 식별 → 영향분석 → 우선순위 → 복구목표 → 자원 산정. MTPD · RTO · RPO · MBCO.
- **DRS — 시스템:** Mirror → Hot → Warm → Cold. 운영 → 대기 → 일부 → 공간. 동기·비동기 복제 / Failover·Failback.

## 8. 공부 우선순위

| 토픽 | 권장 비중 | 반드시 외울 것 |
|---|---:|---|
| BCP | 40% | 수립 절차·검증방안 |
| DRS | 30% | 구축 유형 비교·구성도 |
| BIA | 20% | 복구지표·시간축 구성도 |
| BCM | 10% | 정의·PDCA 구성도 |

네 토픽을 통합해서 공부한다는 전제로 정한 권장 비중이며 실제 기출 빈도나 학원 중요도 순위는 아니다. 절차와 구성도는 학습용 대표 형태이며 실제 설계는 달라질 수 있다.

**BCM은 관리하고, BIA는 분석하고, BCP는 계획하고, DRS는 구현한다.**
