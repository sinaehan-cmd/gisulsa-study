# 1. 가상 메모리 ★셀테 2번

## 1) 사람말 원리

프로그램 A와 B가 **똑같이 가상 주소 1000**을 써도 된다. 각 프로그램에 사용하는 **페이지 테이블이 다르기 때문**이다. A의 1000은 RAM의 한 위치로, B의 1000은 다른 위치로 연결될 수 있다. 같은 프로그램의 페이지가 RAM에서 디스크로 내려갔다가 다른 RAM 위치로 올라와도 **프로그램이 쓰는 가상 주소는 유지**된다.

- **가상 주소**: CPU가 프로그램 실행 중 사용하는 논리적 메모리 주소
- **가상 주소 공간**: 해당 프로세스에서 사용할 수 있도록 정의된 가상 주소들의 전체 범위. 별도 장치가 아님.
- **물리 주소**: 실제 물리 메모리에서의 주소
- **스왑/페이지 파일**: 필요 시 페이지 내용을 디스크에 보관하는 장소. **가상 주소 공간 자체가 아님**.

## 2) 정의 · 특징

**정의(기술사 답안형)**: 가상 주소와 물리 주소의 매핑 및 보조기억장치 활용을 통해 메모리의 논리적 확장과 보호를 지원하는 **메모리 관리 기법**.

| 특징 | 설명 |
|---|---|
| 독립성 | 프로세스별 가상 주소 공간을 독립적으로 제공 |
| 보호·격리 | 페이지 단위로 접근 권한을 검사 |
| 위치 유연성 | 가상 페이지를 떨어진 물리 프레임에 배치 가능 |
| 논리적 확장 | 필요할 때 디스크에 보관된 페이지를 RAM으로 가져올 수 있음 |
| 효율 | 사용 중인 페이지를 중심으로 RAM 활용 |

**[정확성 보완]** 가상 메모리가 항상 디스크를 사용하는 것은 아니다. 주소 공간 분리·매핑이 기본이며 디스크를 통한 페이징은 대표적인 활용이다.

## 3) 역할 분담 — 누가 무슨 일을 하나

| 담당 | 역할 | 비유 |
|---|---|---|
| CPU | 명령 실행 중 데이터 접근 요청 | 요청자 |
| MMU | 주소 변환 및 접근 권한 확인 | 번역가 |
| TLB | 최근 가상 페이지→물리 프레임 변환 결과 저장 | 번역 메모 |
| 페이지 테이블 | 프로세스의 매핑·권한·상태를 기록(RAM에 존재) | 주소 장부 |
| CR3(x86) | 현재 주소 공간의 페이지 테이블 기준 위치 지정 | 장부 위치 표지 |
| 캐시 제어 하드웨어 | 캐시 적중·미스를 판별하고 데이터 접근 | 빠른 서가 |
| 메모리 컨트롤러 | 캐시 미스 시 RAM 읽기·쓰기 제어 | RAM 담당 |
| OS | 매핑 설정, 페이지 폴트 처리, 프레임 할당·교체 | 관리자 |
| DMA 하드웨어 | 일부 I/O에서 장치와 RAM 사이 데이터 전송 보조 | 운반 담당 |

- **CPU 내부(일반적인 x86 설명)**: MMU·TLB·CR3
- **RAM**: 페이지 테이블, 현재 적재된 페이지
- **디스크**: 필요 시 스왑/파일의 페이지 내용
- OS 역시 CPU가 실행하는 코드다. 페이지 교체·매핑 변경을 할 때 커널 코드가 동작한다.

## 4) 주소 변환 구성도

```text
[OS가 프로세스 전환 시 CR3 설정] ──> [CPU의 CR3: 현재 페이지 테이블 기준 위치]
                                              │ (TLB 미스 시 참조)
[CPU: 프로그램 A의 가상 주소 1000 요청]         │
                    │                         │
                    ▼                         ▼
            [MMU: TLB 먼저 확인] ──미스──> [RAM의 페이지 테이블 조회]
                    │                         │
                 적중│                    유효한 매핑
                    └──────────┬──────────────┘
                               ▼
                         [물리 주소 확인]
                               ▼
                        [CPU 캐시 조회]
                          │        │
                        적중      미스
                          │        ▼
                          │   [메모리 컨트롤러 → RAM]
                          └────────┬───────────────
                                   ▼
                              [CPU에 데이터]

페이지가 RAM에 없거나 권한 위반이면: 페이지 폴트 예외 → OS 처리
```

**[정확성 보완]** TLB가 적중하면 보통 페이지 테이블을 다시 읽지 않는다. 실제 L1 캐시는 주소 변환과 조회가 겹칠 수 있으며, 위 구성도는 학습용 단순화다.

## 5) 페이지 아웃 → 페이지 인: 전체 연결

```text
(처음) A의 가상 페이지 X → 물리 프레임 5 (RAM에 있음)
    ↓ OS가 페이지 회수 결정
(페이지 아웃) 필요한 경우 디스크에 페이지 내용 기록
    ↓ A의 해당 페이지는 RAM에 없다고 매핑 상태 변경
    ↓ 프레임 5는 다른 용도로 재사용 가능
(나중) CPU가 A의 동일한 가상 주소 재접근
    ↓ TLB/페이지 테이블로 확인했더니 현재 RAM에 없음
(페이지 폴트: 동기적 예외)
    ↓ OS가 원인 확인, 필요하면 빈 프레임 확보/다른 페이지 교체
    ↓ 디스크의 내용 또는 적절한 원본에서 새 프레임 9로 페이지 인
    ↓ 페이지 테이블 갱신, 필요한 TLB 일관성 유지
(재실행) A의 가상 주소는 그대로! → 물리 프레임 9
```

- **페이지 인**: 필요한 페이지 내용을 RAM으로 가져옴.
- **페이지 아웃**: 페이지를 RAM에서 회수하면서 필요 시 내용을 보조기억장치에 기록.
- **페이지 폴트**: 현재 매핑 상태 또는 권한상 메모리 접근을 처리할 수 없어 발생하는 **예외(Exception)**.
- **[정확성 보완]** 페이지 폴트가 항상 디스크 I/O로 이어지지는 않는다(미할당 페이지 최초 할당, 공유 매핑의 쓰기 시 복사 등). 권한 위반으로 종료될 수도 있다.

## 6) 언제·어디에·누구를·얼마나 — 관리 기법 4가지 ★셀테 2번 가

| 정책 | 핵심 질문 | 대표 방식 | 시험 포인트 |
|---|---|---|---|
| **반입(Fetch)** | 언제 RAM으로 가져올까? | 요구 페이징, 예상 페이징 | 필요한 때 vs 미리 |
| **배치(Placement)** | 어디에 둘까? | 연속 할당에서 최초·최적·최악 적합 | 페이징의 빈 프레임 선택과 구별 |
| **교체(Replacement)** | 누구를 내보낼까? | FIFO, LRU, LFU, OPT | Belady 모순은 FIFO에서 가능 |
| **할당(Allocation)** | 프레임을 얼마나 줄까? | 균등/고정, 비례, 우선순위 등 | 너무 적으면 스레싱 위험 |

### 반입

- **요구 페이징(Demand Paging)**: 실제 필요해졌을 때 적재. 불필요한 반입 감소, 초기 폴트 증가 가능.
- **예상 페이징(Prepaging)**: 곧 필요할 것으로 예상되는 페이지를 미리 적재. 적중 시 폴트 감소, 오예측 시 낭비.

### 배치

| 연속 메모리 할당 방식 | 선택 기준 |
|---|---|
| 최초 적합(First Fit) | 처음 만나는 충분한 크기의 빈 공간 |
| 최적 적합(Best Fit) | 들어갈 수 있는 가장 작은 빈 공간 |
| 최악 적합(Worst Fit) | 가장 큰 빈 공간 |

**[정확성 보완]** 이 세 기법은 주로 **가변 분할·연속 메모리 할당** 설명에 쓰인다. 페이지 기반 페이징에서는 크기가 같은 빈 물리 프레임에 적재하므로 같은 설명을 그대로 적용하지 않는다.

### 교체

| 알고리즘 | 교체 기준 | 특징 |
|---|---|---|
| FIFO | 가장 먼저 들어온 페이지 | 단순, **Belady 모순** 가능 |
| LRU | 가장 오래 참조되지 않은 페이지 | 시간 지역성 활용 |
| LFU | 참조 빈도가 가장 적은 페이지 | 과거 참조 횟수 활용 |
| OPT | 미래에 가장 늦게 다시 참조될 페이지 | 비교용 이론적 최적 |

### 할당

- **고정 할당**: 프로세스별 프레임 수를 고정하는 정책. *(균등 할당과 동일한 뜻은 아님)*
- **비례 할당**: 프로세스 크기 등에 비례해 프레임 배정.
- 프레임 부족 → 페이지 폴트 증가 → 스레싱 가능.

## 7) 지역성(Locality)이 페이징에 가지는 의미 ★셀테 2번 다

**정의:** 프로그램이 짧은 시간 동안 일부 주소·데이터를 집중적으로 참조하는 성질.

| 유형 | 설명 | 예시 |
|---|---|---|
| 시간 지역성 | 최근 사용한 데이터를 다시 사용 | 반복문 변수 |
| 공간 지역성 | 인접 주소를 곧 사용 | 배열 순회 |
| 순차적 접근 | 연속된 주소를 순서대로 접근 | 순차 명령어 실행 |

**워킹셋(Working Set)**: 최근 일정 참조 구간에서 사용한 **서로 다른 페이지들의 집합**. 이 페이지들을 RAM에 충분히 유지하면 페이지 폴트가 줄어든다.

| 페이징에서 의미 | 설명 |
|---|---|
| 적은 프레임으로 실행 | 모든 가상 페이지가 동시에 RAM에 있을 필요는 없음 |
| 교체 정책 근거 | LRU는 시간 지역성을 활용 |
| 예상 반입 근거 | 공간 지역성을 이용하여 인접 페이지 예상 |
| TLB 활용 | 같은 페이지 재참조 시 주소 변환 재사용 |
| 스레싱 방지 | 워킹셋을 충족하도록 프레임 관리 |

## 8) 스레싱(Thrashing)

**정의:** 과도한 페이지 폴트와 페이지 교체 때문에 유용한 실행보다 메모리 이동에 많은 시간을 소비하여 성능이 저하되는 현상.

**원인:** 물리 프레임 부족 · 지나친 다중 프로그래밍 · 워킹셋 미충족.

```text
동시 실행도 증가 → 메모리 압박 증가 → 페이지 폴트 증가
          → 페이지 인/아웃 반복 → CPU 유효 작업 감소
```

| 해결 | 핵심 |
|---|---|
| 워킹셋 관리 | 자주 사용하는 페이지 집합을 유지할 프레임 확보 |
| PFF(Page Fault Frequency) | 폴트 빈도에 따라 프레임 조절 |
| 다중 프로그래밍 정도 조절 | 동시 메모리 압박 줄이기 |
| RAM 증설 | 물리적 여유 확보 |

## 9) AI 응용 — Paged Attention ⚪ (원본: 140회 컴시응 1교시)

**정의:** LLM 추론 시 **KV 캐시를 고정 크기 블록으로 관리**하고 블록 테이블을 사용해 비연속 메모리 위치와 연결하는 기법.

| 구분 | 핵심 |
|---|---|
| 배경 | 연속·과다 예약으로 인한 KV 캐시 메모리 낭비 |
| 원리 | 논리 블록 → 물리 블록 매핑, OS 페이징과 유사 |
| 구성 | 블록 테이블, 논리/물리 블록, KV 캐시 |
| 기대효과 | 단편화·예약 낭비 감소, 병렬 요청 처리량 향상 |
| 대표 구현 | vLLM의 PagedAttention |

**[정확성 보완]** 원본의 특정 낭비율·처리량 개선 배수는 하드웨어와 워크로드에 따라 달라지므로 보편적인 확정 수치로 암기하지 않는다.

# 2. 메모리를 나누는 방법 — 페이징·세그먼테이션 ★셀테 2번 나

## 1) 페이징(Paging)

**정의:** 가상 메모리를 고정 크기 페이지, 물리 메모리를 같은 크기의 프레임으로 나누어 매핑하는 메모리 관리 기법.

- **페이지(Page)**: 가상 주소 공간의 고정 크기 단위.
- **프레임(Frame)**: RAM의 같은 크기 물리 블록.
- 주소 = **페이지 번호 + 오프셋**, 크기는 플랫폼에 따라 다름(4KB, 일부 2MB·1GB 대형 페이지 등).
- 외부 단편화 완화(일반적인 순수 페이징에서는 발생하지 않음), 마지막 페이지 등의 **내부 단편화** 가능.

## 2) 세그먼테이션(Segmentation)

**정의:** 프로그램의 논리적 기능 단위를 크기가 가변적인 세그먼트로 구분하여 메모리를 관리하는 기법.

- 세그먼트: 코드·데이터·스택 등 의미 단위.
- 주소 = **세그먼트 번호 + 오프셋**.
- 논리 단위별 보호·공유에 적합, 가변 크기 배치 시 **외부 단편화** 가능.

## 3) 페이징 vs 세그먼테이션 비교

| 항목 | 페이징 | 세그먼테이션 |
|---|---|---|
| 분할 기준 | 고정 크기 | 논리적 의미 |
| 단위 크기 | 동일 | 가변 |
| 주소 형식 | 페이지 번호 + 오프셋 | 세그먼트 번호 + 오프셋 |
| 매핑 정보 | 페이지 테이블 | 세그먼트 테이블(기준·길이 등) |
| 단편화 | 내부 단편화 가능 | 외부 단편화 가능 |
| 특징 | 불연속 물리 프레임 활용 | 논리적 보호·공유 표현 쉬움 |
| 한계 | 페이지 테이블 부담 | 연속 배치 시 빈 공간 문제 |

## 4) 단편화(Fragmentation)

- **내부 단편화**: 할당받은 블록 **안**에 사용하지 못하는 공간 존재. 예: 4KB 페이지 3개에 10KB 저장 → 마지막 2KB 여유.
- **외부 단편화**: 사용 가능한 빈 공간이 블록 **사이**에 흩어져 연속 할당이 어려움.

```text
연속 배치 예시
[A 30][빈 10][C 20][빈 40]
총 빈 공간은 50이지만, 45 크기 요청은 연속 공간이 없어 배치 불가
```

대응: 외부 단편화는 압축(Compaction), 인접 빈 공간 통합(Coalescing), 페이징 도입 등으로 완화.

## 5) 페이지드 세그먼테이션 (원본: 학원 2026.04 1교시)

**원리:** 프로그램을 논리적 세그먼트로 구분하고, 각 세그먼트를 다시 페이지 단위로 나누어 물리 프레임에 배치.

```text
[세그먼트 번호 + 페이지 번호 + 오프셋]
       ↓ 세그먼트 테이블
       ↓ 해당 세그먼트의 페이지 테이블
       ↓ 물리 프레임 번호 + 오프셋
```

- 장점: 논리 단위의 보호·공유 + 페이지 기반 불연속 배치.
- 단점: 다단계 주소 변환과 관리 오버헤드, 내부 단편화 가능.
- **암기:** 세그먼트로 **규칙**, 페이지로 **자리**.

## 6) 페이지 테이블이 너무 클 때 — 종류 ★빠뜨리지 않기

> 예: 4GiB의 가상 공간 / 4KiB 페이지 = 약 **104만 페이지**. 단일 거대 테이블은 비효율적일 수 있음.

| 종류 | 원리 | 장점 | 한계 |
|---|---|---|---|
| **계층적 페이지 테이블** | 여러 단계로 분리, 필요한 하위 테이블만 구성 | 사용하지 않는 주소 범위의 테이블 절약 | 여러 단계 조회 부담 |
| **역 페이지 테이블(Inverted)** | 물리 프레임을 기준으로 어느 프로세스의 어느 가상 페이지인지 기록 | 물리 프레임 수에 비례한 관리 규모 | 매핑 검색 복잡, 해시 등으로 보완 |
| **해시 페이지 테이블(Hashed)** | 가상 페이지 번호 등을 해시하여 대응 항목 탐색 | 큰 가상 주소 공간에서 효율적인 탐색 가능 | 충돌 처리 필요 |

**암기:** **계층적 = 목차처럼 나눔 / 역 = 물리 프레임 기준 / 해시 = 해시로 찾음**.

**[정확성 보완]** 역 페이지 테이블은 단순히 숫자 주소만 쓰는 것이 아니라 **프로세스·주소 공간 식별 정보도 함께** 필요하다. 해시 페이지 테이블의 해시는 *암호학적 해시*일 필요가 없고, 목적은 빠른 매핑 탐색이다.

# 3. 프로그램 안쪽 — 메모리 영역·누수·세그폴트

## 1) 프로그램 메모리 주요 영역 (원본: 138회)

```text
(일반적인 프로세스 가상 주소 공간의 개념 예시)
높은 주소  [스택: 호출 정보·일부 지역 변수]  ↓ 성장하는 경우가 많음
           [사용하지 않는 주소 범위]
           [힙: 동적 할당]                  ↑ 성장하는 경우가 많음
           [데이터/BSS: 전역·정적 변수]
낮은 주소  [코드(Text): 실행 명령어]
```

- 실제 배치는 OS·언어·ASLR에 따라 달라진다.
- **코드/데이터/힙/스택은 프로그램의 논리적 영역**이며, 캐시·RAM·디스크 같은 물리적 저장 계층과 다름.

## 2) 메모리 누수(Memory Leak, 원본: 136회)

**정의:** 더 이상 필요하지 않은 메모리를 회수하지 못해 실행 중 사용 가능한 메모리가 감소하는 현상.

| 환경 | 대표 원인·대응 |
|---|---|
| C/C++ | free/delete 누락 → 해제 규칙·스마트 포인터 |
| Java/Python | 필요 없는 객체 참조가 계속 살아 있음 → 참조 해제, 프로파일링 |
| 서버/JVM | 세션·캐시·리스너 등에 객체 누적 → 힙 분석, GC 및 참조 점검 |

- 증상: 메모리 증가, GC 부담, 성능 저하, OOM 가능.
- 현장 연결: JEUS/JVM의 세션 객체 누적, 힙 덤프·프로파일링.

## 3) 세그먼테이션 폴트(Segmentation Fault, 원본: 136회)

**정의:** 프로세스가 유효하지 않거나 허용되지 않은 메모리 주소에 접근하여 발생하는 오류.

예: NULL 포인터 역참조, 잘못된 포인터, 읽기 전용 페이지 쓰기, 스택 오버플로 등.

- **메모리 누수** = 쓰고 난 메모리를 반납·회수하지 못하는 문제
- **세그폴트** = 잘못된 주소에 접근하는 문제
- **[정확성 보완]** 세그폴트라는 이름이 곧 전통적 세그먼테이션 방식만의 오류라는 뜻은 아니다.

# 4. 인터럽트 ★셀테 6번

## 1) 정의

**인터럽트:** 장치 등의 비동기적 요청으로 CPU 실행 흐름을 처리 루틴으로 전환하는 메커니즘. 넓은 교육적 맥락에서는 예외·시스템 콜과 함께 CPU의 제어 전환으로 다루기도 함.

**[정확성 보완]** 페이지 폴트는 엄밀히 **인터럽트(외부 비동기 사건)가 아니라 동기적 예외(Exception)**이다. 다만 CPU가 커널 처리 루틴으로 전환한다는 점에서 흐름은 연계됨.

## 2) 종류

| 구분 | 의미 | 예 |
|---|---|---|
| 외부 인터럽트 | 장치·타이머 등 비동기 요청 | I/O 완료, 타이머 |
| 내부 예외 | 실행 중 동기적으로 발생 | 페이지 폴트, 0 나누기 |
| 소프트웨어 요청 | 프로그램이 의도적으로 커널 서비스 요청 | 시스템 콜 |
| 마스커블 | 일반 인터럽트 마스크로 차단 가능 | 일반 장치 IRQ |
| NMI | 일반 마스크로 차단되지 않음 | 일부 심각한 하드웨어 이벤트 |

## 3) 처리 절차 ★셀테 6번 가

```text
① 사건 발생 / 인터럽트 요청
② 실행 흐름의 안전한 전환 지점 확보
③ 필요한 실행 상태(PC·레지스터 등) 저장
④ 원인 식별 및 적절한 처리 루틴 선택
⑤ ISR(또는 예외 처리 루틴) 수행
⑥ 실행 상태 복원
⑦ 원래 실행 흐름 재개(또는 오류 처리·스케줄링)
```

**암기:** 발생 → 전환 → 저장 → 식별 → 처리 → 복원 → 재개.

**[정확성 보완]** 모든 예외에서 ‘현재 명령어를 완료한 뒤’ 처리하는 것은 아니다. 페이지 폴트는 문제를 일으킨 명령어를 다시 수행할 수 있다.

## 4) 원인 식별·구현 방식 ★셀테 6번 나 (원본: 132회 2교시)

| 방식 | 동작 | 특징 |
|---|---|---|
| 폴링(Polling) | CPU가 장치 상태를 차례로 확인 | 구조 단순, 확인 비용 발생 |
| 데이지 체인(Daisy Chain) | 우선순위 순서에 따라 장치 신호 전달 | 단순, 후순위 대기 불리 |
| 벡터 방식(Vectored) | 벡터 번호를 이용해 처리 루틴 선택 | 빠른 루틴 식별 |

**[정확성 보완]** 폴링은 원칙적으로 **인터럽트를 사용하지 않는 대안적인 장치 확인 방식**이지만, 원본 셀테 비교표 항목을 유지했다.

## 5) 다중 인터럽트 처리 — 원본에 ‘추후 추가’로 표시

- **원본 학습 자료에 본문 없음(미정리)**.
- 참고 개념: 우선순위, 마스킹, 중첩 허용, 처리 중 재진입 여부. *이 항목은 원본 내용을 대체하거나 학습 완료 처리하지 않음.*

# 5. 입출력(I/O) 방식과 DMA

## 1) I/O 방식 3가지

| 방식 | CPU 역할 | 요점 |
|---|---|---|
| Programmed I/O | 상태를 반복 확인하고 CPU가 데이터 이동 | 폴링·CPU 점유 |
| Interrupt-driven I/O | 이벤트 알림 후 CPU가 I/O 처리 | 대기 중 다른 일 가능 |
| DMA | CPU가 전송을 설정, DMA 하드웨어가 데이터 이동 | 대량 전송 시 CPU 부담 감소 |

**[정확성 보완]** ‘1000개 옮길 때 인터럽트 1000번 vs DMA 1번’은 개념적 비유일 뿐 실제 고정 횟수가 아니다.

## 2) DMA(Direct Memory Access)

**정의:** CPU가 데이터 한 단위씩 직접 복사하지 않고 I/O 장치와 메모리 사이의 데이터 전송을 수행하도록 하는 방식.

```text
CPU/드라이버: 전송 대상·방향·크기 등 설정
          ↓
DMA 가능한 장치/컨트롤러: 메모리와 장치 사이 전송
          ↓
전송 완료/오류 알림 → CPU에서 후속 처리
```

- DMA 기능은 별도 컨트롤러나 I/O 장치 내부에 구현될 수 있다.
- 디스크의 페이지 인에도 DMA 기반 전송이 흔히 쓰인다.

## 3) DMA 전송 모드 (원본: 137회)

| 모드 | 의미 |
|---|---|
| 사이클 스틸링(Cycle Stealing) | 버스 사용 기회를 짧게 확보하며 전송 |
| 버스트(Burst) | 연속된 전송 구간을 확보 |
| 투명(Transparent) | 다른 주체가 버스를 사용하지 않을 때 전송 |

**연결:** 여러 버스 마스터가 전송 자원을 요구하면 **버스 중재**가 필요하다.

# 6. 버스 중재 (Bus Arbitration)

## 1) 정의

**여러 장치가 공유 버스를 동시에 사용하려 할 때 버스 사용 권한과 순서를 결정하는 제어 기법**.

## 2) 중재 방식 (원본: 137회)

| 방식 | 방법 | 장단점 |
|---|---|---|
| 직렬(데이지 체인) | 우선권을 순서대로 전달 | 구조 단순 / 위치 편향 |
| 병렬(중앙 집중) | 중재기가 여러 요청을 비교 | 빠른 선택 / 회로 비용 |
| 분산 | 장치들이 공통 중재 규칙으로 경쟁 | 중앙 의존 감소 / 구현 복잡 |

## 3) 우선순위

- **고정 우선순위**: 순위 일정. 낮은 우선순위 장치의 기아 가능.
- **회전/라운드로빈**: 사용 후 우선순위를 뒤로 이동. 공정성 개선.
- **[정확성 보완]** DMA가 언제나 CPU보다 우선순위가 높은 것은 아니다. 시스템 정책과 버스 규격에 따라 다르다.

# 전체 흐름 — 크롬에서 데이터를 읽을 때

```text
① OS가 크롬 프로세스의 가상 주소 공간·페이지 테이블을 마련
② CPU가 명령 실행 중 가상 주소를 생성
③ MMU가 TLB를 먼저 확인; 미스 시 CR3가 가리키는 페이지 테이블 조회
   ├─ 유효한 RAM 매핑 → 물리 주소 확인 → 캐시 조회
   │                      ├─ Hit: 캐시에서 CPU로 데이터
   │                      └─ Miss: 메모리 컨트롤러를 거쳐 RAM에서 데이터
   └─ 페이지 부재·권한 위반 → 페이지 폴트 예외
                           └─ OS가 원인 판별
                               ├─ 정상 처리 불가: 오류 처리
                               └─ 처리 가능: 프레임 확보, 필요시 교체
                                   → 필요시 디스크 I/O(DMA 활용 가능)
                                   → 페이지 테이블/TLB 관련 상태 갱신
                                   → 명령어 재실행
④ 워킹셋에 비해 프레임이 부족하면 페이지 폴트 증가 → 스레싱 위험
⑤ 여러 장치가 같은 버스 자원을 요구하면 버스 중재 수행
```

| 토픽 | 최소 인출 |

| 🔴 페이징·세그먼트 ★셀테 2 나 | 고정 vs 가변 · 페이지/프레임 · 내부 vs 외부 단편화 · 페이지드 세그먼테이션 |
| 🟡 페이지 테이블 관리 | 계층적 · 역 · 해시 (반드시 포함) |
